Two-phase runtime pipeline (fast + stable)

Goal: show “suspicious” quickly, confirm within ~20 seconds.

Defaults (configurable):

BASELINE_WINDOW_SEC = 10

CONFIRM_WINDOW_SEC = 20 # decision by 20s (fits 15–30s requirement)

COOLDOWN_SEC = 15

Per-device state machine:

IDLE

CONFIRMING (collecting confirm window after suspicion)

COOLDOWN

Phase 1: suspicion gate (physics-based)

This phase should be fast and sensitive; it starts the confirm window.

Maintain rolling baselines from last ~60 seconds:

rolling median or EWMA for pm25_base, pm1_base, pm10_base, gas_base, rh_base
Maintain a smoothed derivative (diff over last 3 samples):

pm25_slope_smooth

Compute:

d_pm25 = pm25 - pm25_base

ratios: r_pm1_pm25 = pm1/(pm25+eps), r_pm1_pm10 = pm1/(pm10+eps)

Suspicion trigger (configurable):

d_pm25 >= D_PM25_SUS

AND pm25_slope_smooth >= SLOPE_SUS

optional: ratio gate if pm1 present

When triggered:

freeze t0 = now

freeze baseline snapshot values (pm25_base, etc.)

create events doc with status="suspected" (dashboard update)

move to CONFIRMING

Phase 2: confirmation window (20 seconds)

Collect samples from [t0, t0+20s]. At t_decision, compute event features from:

baseline segment [t0-10s, t0] (or frozen baseline snapshot)

event segment [t0, t0+20s]

Then run the ensemble predictor ONCE and write final event classification.

After decision, enter COOLDOWN.

Feature engineering (event-level, no pandas)

Implement a FeatureEngine that operates on python lists/deques. O(n) is allowed at decision time because window is small (~30s of data), but NOT per sample.

Compute (minimum set; floats; None if uncomputable):

start values: pm1_start, pm25_start, pm10_start, humidity_start, gas_start, temp_start

baselines (median baseline window): pm25_base, pm1_base, pm10_base, gas_base, humidity_base

r_pm1_pm25_peak, r_pm1_pm10_peak

humidity/gas dynamics: humidity_delta_20s, humidity_slope_0_10s, gas_delta_20s, gas_slope_0_10s

Ensemble predictor (multi-class soft voting)

Implement EnsemblePredictor that loads multiple models (joblib) and outputs probs over CLASS_ORDER.

Models supported:

XGBoost: xgb_model.joblib

RandomForest: rf_model.joblib

LogisticRegression or SVC(probability): lr_model.joblib or svc_model.joblib

Rules:

Every model must output predict_proba aligned with CLASS_ORDER.

Combine with weighted mean PER CLASS:

p_ens[c] = sum_i w_i * p_i[c] / sum_i w_i

If any model fails to load/predict, skip it. Require at least 1 model. If none, fallback to conservative rules that classify as normal with low confidence.
